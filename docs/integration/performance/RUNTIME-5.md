## 返回错误的受控复现

此前只用普通 `.html` 静态地址验收，漏掉了无后缀地址。新增本地托管模型把 `project.html` 重定向到 `/project`、`works.html` 重定向到 `/works`：旧版 site.js 的精确 `.html` 判断失败，详情没有装配关闭控制，出现左上角旧箭头；点击后 WORKS 根入口又被默认当作 HOME。旧版真实浏览器输出为箭头 x=40、class 为空，返回章节 home。

现在路由统一识别两种地址，HTML 本身即为右上角白色 X，并明确配置 WORKS 回退与作品 ID。关闭绑定由详情模块独立、幂等完成，不再依赖通用路由分支；模拟嵌入详情的通用路由脚本失败，仍验证平滑返回原 WORKS。详情进入前建立明确的 WORKS 历史条目；X 只对可验证的本次条目使用后退，否则显式回到 WORKS。嵌入详情通过既有 800ms 反向共享元素动画关闭，不重载外层文档。修复后的同一重定向模型返回 works、作品 ID 保留；桌面与手机均实际点击验证。本地模型不等于线上 HTTP 头抓包，不声称已经确认托管服务器的响应配置。

## 真正观察到的问题与处理

1. **软件 WebGL 绘制占据主线程时间**。CPU 样本以 native/program 为主，而不是 bubbles.js 长时间 JS 计算，且驱动明确为 SwiftShader。仅对软件渲染限制背缓冲约36万像素，空闲最多12次/秒、交互阶段24次/秒；正常硬件仍保留原 DPR 上限及绘制节奏。shader、气泡轨迹、弹动/点破公式和 DOM 布局未改。软件路径允许边缘精度适当降低以换取响应时间，不删除动效。
2. **轮盘停稳仍空转**。原逻辑每次已吸附后清空 target，下一帧又给相同角度设置 target；关闭自动播放时也维持不必要的 hold 帧。现在只为存在误差的目标吸附，停稳后不再调度。原弹簧与几何参数不变。
3. **CONTACT 每帧重复写相同文本/属性**。原相机状态及按钮文字无变化也替换文本节点、SVG 路径无变化也重写。现在只在值变化时更新，保留原 blur 区域和寻焦曲线。约同样93个对焦回调的节点计数增量从297降至21（包含待回收节点，不等同于内存泄漏）。信息滤镜约1040×268，不是整屏滤镜；本轮未扩大滤镜或改变最终布局。
4. **初始同时启动四章**。现在只加载当前章，访问过的实例保留；未访问的 React 轮盘、其他模块、媒体不提前初始化。离开章暂停其时钟/帧，切换期间冻结离开章的画面。非当前槽 visibility:hidden + inert，移除轨道常驻 will-change，仅在位移期间提示。
5. **未证实的假设不当成结论**。基线在 HOME 已离开并稳定后，其 rAF 本来就是0，未发现持续离屏 WebGL 空转；同样没有证据证明所有卡顿来自重复监听泄漏。优化后新增8个固定生命周期监听，访问完四章后的监听数在重复导航中没有持续增长；章节实例不重复初始化。观察到的 JS 堆并不能推断 GPU 显存或长期泄漏，未作此类结论。
